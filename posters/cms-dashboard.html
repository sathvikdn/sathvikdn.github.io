Real-Time CMS Monitoring — Built Entirely with AI

A full-stack operational dashboard for the Kafka-based CMS data pipeline, built from scratch using AI pair programming. Embedded directly inside Pega, providing 24/7 visibility across 6 APAC markets with 50+ Kafka topics and 20+ Kubernetes nodes.

Our Kafka-based CMS pipeline processes data across 6 APAC markets with 50+ Kafka topics on 20+ Kubernetes nodes. There was zero operational visibility — failures were discovered hours later via email complaints. AI was used to build a complete monitoring dashboard from scratch in days, not months. It runs inside Pega via Data Pages, with dark/light themes, real-time charts, node health tracking, one-click requeue, and historical comparison — capabilities that would normally require a dedicated engineering team.

What the Dashboard Does

⚠

Broken Query & Failed Merge Detection

Surfaces every failed Kafka message and failed merge query instantly — filterable by topic, table, error type with full JSON inspection

♥

Node Health & Zombie Detection

Minute-level heartbeat grid for 20+ nodes. Detects vanished pods, K8s rotations, idle nodes, and stream session staleness automatically

⇄

One-Click Requeue

Select failed messages, view/edit JSON payload, requeue single elements or full messages back to Kafka — all from the browser

⏱

Historical Comparison

Compare any two time windows side-by-side: throughput, errors, node health, topic performance — with auto-generated delta analysis

☷

Embedded in Pega

No external infra. Runs as a single HTML section inside Pega, fetching data through Pega Data Pages — zero deployment overhead
